# ربط Render بالشيت نفسه

الكود ينفذ اتصالًا من خادم Next.js إلى Apps Script بتوقيع HMAC-SHA256. لا تُرسل الأسرار للمتصفح. جميع عمليات القراءة والكتابة تمر عبر نفس دوال Phase 01 وقفلها وسجل طلباتها، وليس باستبدال الشيت بملف JSON أو استيراد Excel.

**الحالة: تنفيذ واختبارات محلية؛ لم يتم نشر هذا الفرع على Render، أو تفويض Google، أو قراءة/كتابة الشيت الحي من Codex.** النسخة العامة الحالية تظل demo إلى أن يُدمج الفرع وتُضبط البيئة. لا تُستخدم بيانات حقيقية مع إعدادات render.yaml التجريبية.

## ترتيب التفعيل على نسخة Google اختبار خاصة

1. احفظ نسخة المشروع الحالي. استبدل ملف السكربت المجمع وحده بمحتوى `phase01/install/ROJBEY_ALL_IN_ONE.gs` من هذا الفرع. لا تضف ملفات `.gs` المنفصلة بجانبه. احفظ Index.html بصورة منفصلة. التحديث لا يمسح Script Properties أو الربط السابق، ولا يلزم إعادة setup إذا اكتمل بالفعل.
2. تأكد أن نفس حساب مديرة الإعداد هو الذي ينشر الجسر. شغّل `RB_audit` ثم `RB_health` من المحرر، وراجع النتيجة والمخطط. إذا لم يكتمل التجهيز، اتبع backup/setup الخاص بـPhase 01 على نسخة الاختبار فقط.
3. شغّل `RB_enableRenderBridge` من المحرر. يعرض مفتاحًا في نافذة خاصة داخل الشيت ويحفظه في Script Properties. انسخ القيمة مباشرة إلى `CRM_SHEETS_SECRET` في Render. لا تشاركها في المحادثة أو GitHub أو console. الدالة لا تعيد المفتاح في execution logs، وإعادة تشغيلها تظهر نفس المفتاح.
4. Deploy → New deployment → Web app: **Execute as Me** (حساب مديرة الإعداد المربوط)، و**Who has access: Anyone** حتى يستطيع خادم Render الوصول دون شاشة Google login. هذه إعدادات الجسر الجديد فقط؛ تختلف عن واجهة Sidebar القديمة التي تتطلب هوية المستخدم. لا تجعل ملف الشيت نفسه عامًا. إذا منع Workspace نشر Anyone، لا توسع مشاركة الشيت؛ هذا المسار يحتاج حل OAuth مختلفًا.
5. انسخ رابط `/exec` إلى `CRM_SHEETS_URL` في Render. GET لهذا الرابط لا يعرض بيانات العميلات؛ doPost يرفض الطلبات دون توقيع. هذا الرابط ليس واجهة العميل، ولا يُستخدم بدل رابط Render. بعد تحديث المصدر لاحقًا: Manage deployments → Edit → New version.
6. جهّز حساب المديرة أولًا باستخدام `node scripts/create-account.mjs` في جهاز موثوق. يطلب كلمة المرور دون عرضها ويطبع JSON يحتوي hash مملحًا فقط. ضعه في `CRM_USERS_JSON` كـarray. الدور يُحدد هنا على الخادم، ولا يختاره المستخدم عند الدخول. حسابات الدخول مستقلة عن قائمة الموظفات المسؤولة عن الإسناد، التي طلب المستخدم تأجيلها.
7. حدّث بيئة Render يدويًا (مع مراجعة الفرع ودمجه أولًا):

| المتغير | القيمة |
| --- | --- |
| CRM_DATA_PROVIDER | sheets |
| CRM_DEMO_MODE | false — مطلوب حرفيًا |
| CRM_SHEETS_URL | رابط الجسر `/exec` |
| CRM_SHEETS_SECRET | المفتاح ذو 64 خانة من النافذة الخاصة |
| CRM_USERS_JSON | الحسابات الفردية وأدوارها وhashes |
| CRM_SESSION_SECRET | مفتاح عشوائي خاص ≥32 حرفًا؛ احتفظ به خارج Git |
| CRM_APP_ORIGIN | عنوان Render الخارجي الدقيق، دون slash أخير |

الخدمة الحالية Blueprint-managed: ملف render.yaml الموجود ما زال خاصًا بالعرض. عند التفعيل راجع قيم الموفر ووضع التجربة فيه أيضًا قبل أي Blueprint sync لاحق، حتى لا يعيد إعدادات العرض فوق إعدادات الخدمة الحية.

لا تستخدم NEXT_PUBLIC_ لأي متغير أعلاه. لا تنسخ كلمات مرور مشتركة من demo. `CRM_ADMIN_PASSWORD` و`CRM_STAFF_PASSWORD` لا يُستخدمان لموفر sheets. اختيار sheets مع demo=true يمنع الدخول والبيانات بدل كشفها. تغيير إعداد الحسابات يلغي صلاحية جلساتها السابقة. لا يوجد fallback إلى seed إذا تعطل Google.

8. أعد نشر نسخة الكود التي تتضمن هذا الفرع، ثم اختبر تسجيل الدخول والقراءة أولًا. تحقق من عدد العميلات والمجموعات التاريخية والحالات والقوائم. لا تستورد بيانات demo. تظل حالات «مستورد» كذلك، وتظل التواريخ الأصلية الفارغة فارغة.
9. جرّب على نسخة الاختبار إضافة عميلة اختبار وتعديلها ثم أعد تحميل الصفحة وافتح الشيت لتطابق ID. اختبر منع الفريق من تعديل ملف عميلة، ورفض المستخدم غير المسجل، وتعطل الجسر دون بيانات بديلة. المواعيد والمتابعات تحتاج قائمة موظفات معتمدة، وهي مؤجلة حاليًا؛ لا تختبر الإسناد بأسماء تاريخية غير معتمدة.
10. بعد اعتماد القائمة لاحقًا، اختبر المواعيد/الإلغاء/تطابق الوقت والمتابعات/الإكمال/الإلغاء من Render وSidebar على نفس نسخة الاختبار. لا تُفعّل الإنتاج إلا بعد تحقق حي موثق ونسخة احتياطية ومراجعة الربط بالملف الصحيح.

## السلوك والحدود

- واجهة Render تستخدم خيارات الشيت، وتحافظ على القيم التاريخية خارج القائمة عند تعديل الحقول الأخرى. لا تسوّي source مع channel ولا تعيد تعيين staff. الحقول القديمة غير المعروضة لا تُرسل ضمن patch، فيحتفظ بها المصدر.
- لا توجد مدة موعد في المخطط الحالي. الواجهة تعرض «غير محددة»، والتحقق الحي يمنع نفس وقت البداية للموظفة أو العميلة؛ لا يدّعي منع تداخل مدد غير موجودة. قواعد demo للمدة تبقى خاصة بالبيانات التجريبية.
- المتابعات الملغاة محفوظة وتُستبعد من المستحق. معرّفات العملاء المفقودة/المكررة تمنع تحميل ملفات قابلة للتعديل بدل توليد IDs جديدة تلقائيًا.
- يتحقق الجسر من التوقيع والزمن والهوية الخادمة وحساب Google الفعال ويقبل قائمة عمليات محددة فقط، ولا يسمح بتشغيل setup أو backup عبر HTTP. كل عملية كتابة تحتاج requestId ثابتًا. منع إعادة envelope عبر CacheService احتراز مؤقت؛ حماية تكرار الكتابة الدائمة تعتمد سجل الطلبات الأصلي.
- عند نتيجة حفظ غير مؤكدة، زر إعادة المحاولة يعيد نفس payload وrequestId، ولا يسمح بإرسال عملية مختلفة قبل حسم السابقة. لا تغلق الصفحة أو تسجل الخروج قبل الحسم؛ الطلب المعلق في ذاكرة الصفحة فقط، والتعافي بعد إغلاقها يحتاج مراجعة journal من المديرة. لا تكرر إدخال السجل يدويًا.
- الحسابات مخزنة كـhashes في بيئة الخادم. لا توجد استعادة ذاتية لكلمة المرور أو MFA أو إدارة الحسابات من الواجهة. حد محاولات الدخول في ذاكرة عملية واحدة، وليس خدمة حماية موزعة. راجع متطلبات المؤسسة قبل تعميم الوصول.
- جميع حسابات Render المصرح بها ترى بيانات الشيت المتاحة للتطبيق. دور الفريق ممنوع من تعديل ملف عميلة، لكن يمكنه الإضافة والمواعيد والمتابعات. لا توجد صلاحيات حسب صف/فرع.
- ScriptLock يعمل داخل مشروع Apps Script فقط؛ التعديل اليدوي أو مشروع ثانٍ خارج هذا القفل. لا توجد مزامنة محلية أو Meta أو مالية.
- لتعطيل الجسر فورًا: اضبط `RB_RENDER_ENABLED=false` في Script Properties. لتدوير مفتاحه: احذف RB_RENDER_SECRET ثم شغّل RB_enableRenderBridge وانقل القيمة الجديدة سرًا إلى Render. لا تعِد تشغيل demo على ملف يحتوي بيانات حقيقية.

## الاختبارات

`npm test` يشغل اختبارات المجال والحسابات وربط توقيع Node بالـApps Script نفسه عبر خدمات Google محاكاة: قراءة المخطط الحقيقي (بسجلات synthetic)، طلبات موقعة، تلاعب/انتهاء/إعادة envelope، رفض مالك خاطئ أو دالة غير مسموحة، صلاحيات الفريق، idempotency وسجل الحساب. اختبارات المتصفح تشمل واجهة Sheets مع API مُحاكى للحالات التاريخية وإعادة الطلب غير المؤكد. اختبارات Phase 01 الأصلية منفصلة. لا يثبت أي منها Google OAuth أو نشر Render أو persistence الحي.

آخر تحقق محلي لهذا التغيير: typecheck وbuild نجحا؛ `npm test`: 10 اختبارات ناجحة؛ Phase 01: 38؛ Playwright: 4، منها اختبار UI مع API محاكى للشيت. نجح أيضًا `npm run test:production` للموفر المحلي و`npm run test:sheets-production` لحسابات sheets ورفض demo والصلاحيات وفشل القراءة المغلق عند غياب إعداد Google. الاختبار الأخير لا يتصل بـGoogle.
