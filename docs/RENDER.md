# نشر عرض تجريبي على Render

`render.yaml` يجهّز Web Service بخطة Free، وبيانات **وهمية فقط**. لا يتطلب إدخال Google أو Meta credentials، ويولّد Render مفتاح الجلسة الخاص تلقائيًا. يستخدم التطبيق `RENDER_EXTERNAL_URL` لفحص Origin خلف HTTPS الخاص بـRender، ويمكن تجاوز ذلك بـ`CRM_APP_ORIGIN` عند إضافة domain مخصص.

## النشر

1. اربطي حساب Render بحساب GitHub واسمحي بالوصول إلى `hemo143/CRM-Rojbey` فقط.
2. من Render اختاري **New → Blueprint** ثم اختاري المستودع وفرع `main`.
3. راجعي أن الخطة **Free** واسم الخدمة `rojbey-crm-demo`، ثم أنشئي Blueprint.
4. انتظري نجاح البناء وظهور **Live**، وافتحي العنوان الذي يعطيه Render. لا يوجد عنوان منشور قبل إتمام هذه الخطوة.
5. اختاري دخول النسخة التجريبية، وجرّبي إضافة عميلة وموعد. اختيار دور المديرة مفتوح للجميع في هذا العرض؛ لا تضعي بيانات حقيقية.

لو استخدمتِ **New → Web Service** بدل Blueprint، اضبطي:

- Runtime: Node، وNode 24.
- Build Command: `npm ci --include=dev && npm run build`.
- Start Command: `npm run start:render`.
- Instance: Free، وHealth Check: `/api/auth`.
- متغيرات البيئة طبقًا لـ`render.yaml`؛ أنشئي قيمة عشوائية خاصة لـ`CRM_SESSION_SECRET` في لوحة Render ولا ترسليها في المحادثة.

## حدود العرض المجاني

بيانات JSON على نظام ملفات مؤقت، ولذلك قد تُفقد عند restart أو deploy أو إعادة إنشاء الخادم. قد تتوقف الخدمة وقت عدم الاستخدام وتحتاج وقتًا لتستيقظ. هذه النسخة هدفها مشاهدة الواجهة وتجربتها فقط. لا تستخدميها كقاعدة بيانات الشغل.

حفظ البيانات الدائم يحتاج خدمة مدفوعة وقرصًا دائمًا (مع نسخة خادم واحدة)، أو تنفيذ محول Google Sheets/PostgreSQL. لا تضيفي قرصًا أو تغيّري الخطة قبل مراجعة التكلفة. المستخدم لم يفوّض شراء خطة مدفوعة.

لا ترفعي `.env.local` أو `.data` إلى GitHub. ضبط `CRM_DEMO_MODE=false` وكلمات مرور وظيفية يسمح بتجربة حماية الدخول، لكنه لا يستبدل حسابات فردية للموظفات أو متطلبات تشغيل حقيقية موثّقة في README.
