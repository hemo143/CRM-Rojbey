# Phase 01 — تدقيق قبل التنفيذ

تاريخ الفحص: 2026-10-23. نطاق الفحص المؤكد هو الملفات المحلية. وصل رابط الشيت أثناء التنفيذ، لكن طلب القراءة توقف عند شبكة البيئة (CONNECT 403 إلى docs.google.com) قبل التحقق من صلاحيات Google. لا يوجد حساب Google مفوّض للشيت في اتصالات البيئة المرصودة، ولم تُفحص بيانات الملف الحي.

## الأدلة الموجودة

- `docs/skills/rojbey-crm/references/Code.gs`: مصدر Apps Script أولي، وهو المرجع الوحيد المتاح لمخطط Phase 01. يعرّف العملاء (14 عمودًا)، المواعيد (10)، المتابعات (8)، وسجل العمليات (4).
- نسخة مطابقة محفوظة خارج المستودع في `/workspace/rojbey-resources`.
- `ROJBEY_Interactive_CRM_Demo.html` داخل الحزمة: محاكاة محلية بثلاث عميلات وهميات، وليست واجهة `google.script.run`، وليست دليل اتصال بشيت.
- ملفات skills وREADME وSTATUS_CHECKLIST: تاريخ وخطة، وليست إثباتًا لتشغيل النظام.
- تطبيق Next.js الحالي على Render: بيانات JSON تجريبية مستقلة. لا يُعد Phase 01 أو تكامل Google Sheets؛ لن يُستخدم مصدرًا للبيانات الحقيقية ولن يُوسّع في هذه المهمة.
- لم يُعثر على `Index.html` الأصلي، أو XLSX، أو workbook مصدر، أو ZIP الكامل للـPOC في الملفات المتاحة. أسماء هذه الملفات وردت في وثائق قديمة فقط. لا يوجد شعار أصلي متاح يمكن استخدامه كشعار معتمد؛ أيقونات الـskills ليست دليلًا على الشعار المعتمد.
- لا توجد أدوات Google Sheets/Drive/Apps Script متصلة بالجلسة. لا يمكن فحص التبويبات الحقيقية أو سجلاتها أو Named Ranges أو صلاحياتها أو triggers من الملفات المحلية.

## الفجوات في Code.gs الأصلي

1. يقرأ ويكتب بحسب ترتيب الأعمدة فقط؛ لا يتحقق من المخطط أو الأعمدة المكررة/المعاد ترتيبها.
2. `RB_health` و`RB_getData` يستدعيان setup، فتتحول القراءة إلى كتابة غير متوقعة.
3. لا توجد نسخة احتياطية موثقة أو فحص توافق قبل تجهيز ملف غير فارغ.
4. لا توجد قوائم Google Sheets فعلية، أو إعدادات تشغيل وصلاحيات؛ قيم الحالات الافتراضية ثابتة في المصدر.
5. لا توجد واجهة `Index` في الملفات المتاحة، ولا تعديل عميلة أو موعد أو سجل رحلة عميلة كامل.
6. الاسم مطلوب فقط؛ التحقق من التواريخ والوقت والمهام ناقص، وتطبيع الهاتف لا يشمل الأرقام العربية.
7. الحماية من صيغة الخلية لا تشمل البادئة `-` وكل محارف المسافة والتحكم.
8. الاستجابة تقص البيانات بصمت عند 2500 عميلة و400 موعد و500 مهمة.
9. لا توجد معالجة لاستعادة عملية نجحت كتابتها ثم فشل log أو انقطع رد الطلب؛ الإعادة قد تنشئ سجلات مكررة.
10. `getDocumentLock` ليس قفلًا مضمونًا في سياق Web App؛ يلزم ScriptLock للمشروع وربط Spreadsheet ID صريح.
11. مخطط المواعيد لا يحتوي على مدة. الأصل يتحقق من تطابق الموظفة/اليوم/الوقت فقط؛ لا توجد قاعدة موثقة لمدة أو تداخل زمني، ولذلك لن تُخترع مدة.
12. لا توجد لوحة إدارة Sheets-native أو اختبارات تشغيل أو توثيق rollback.
13. البيع والإيجار والمدفوعات والمخزون والتسليم غير ممثلة في المصدر المتاح. لا توجد أسعار أو قواعد خصومات أو refunds أو مدد إيجار مؤكدة.

## قرارات التنفيذ الآمنة

- الاحتفاظ بالمصدر التاريخي كما هو، وإضافة النسخة القابلة للنشر إلى `phase01/` بنفس الدوال العامة المفيدة، مع ملفات إضافية وواجهة حقيقية لـApps Script.
- الحفاظ على أسماء وأعمدة الجداول الأربعة الأصلية، والربط بأسماء الأعمدة، وعدم ترحيل أو حذف أو إعادة ترتيب أي سجل.
- رفض setup على مخطط غير متوافق أو جدول مكافئ محتمل بدل إنشاء نسخ مكررة. يمكن تحديد خريطة التبويبات صراحة بعد التدقيق.
- التحقق من النسخة الاحتياطية ومطابقة المحتوى قبل أي إعداد لملف غير فارغ؛ لا تُدّعى نسخة احتياطية بمجرد وجود اسم ملف.
- إضافة أعمدة داخلية صغيرة للتعافي من إعادة الطلب، وجداول إعدادات وقوائم وDashboard وسجل طلبات، لكل منها غرض وظيفي محدد.
- لا تُملأ بيانات أو أسماء موظفات أو أكواد فساتين وهمية. تُستخرج خيارات القوائم الأولية من قيم الجدول الحالي عند وجودها، وتوثّق القيم الأساسية الموروثة من المصدر؛ القوائم الناقصة تُضبط يدويًا.
- الواجهة/sidebar تستخدم `google.script.run` إلى نفس الشيت، دون fallback إلى mock data.
- لا تُنفّذ مبيعات أو مدفوعات أو توافر فساتين قبل فحص البيانات وتأكيد القواعد. توثّق كمتطلبات متوقفة، وليس ميزات مكتملة.
- لا تُنشأ triggers زمنية أو رسائل أو Meta integration.
- الاختبارات المحلية ستستخدم محاكاة لخدمات Google مع بيانات اختبار معزولة. اختبارات Google الحية، ظهور القوائم الفعلي، التشغيل بصلاحيات الموظفات، والكتابة الحقيقية ستظل غير منفذة حتى إتاحة حساب/شيت اختبار.
